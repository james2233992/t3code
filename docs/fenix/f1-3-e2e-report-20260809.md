## Scope

This candidate completes the local Fenix Code tenancy foundation without changing the original T3 Code views or behavior for normal local sessions.

Implemented:

- nullable local tenancy columns on `projection_projects`: `fenix_company_id`, `fenix_user_id`;
- indexed scoped lookup by `companyId + userId`;
- additive `FenixScopedProjectionSnapshotQuery` service;
- fail-closed scope validation for non-positive, unsafe, or non-finite company/user ids;
- read filtering for projects/workspaces, threads, projected sessions, checkpoints, full snapshots, shell snapshots, archive snapshots, search, counts, and targeted reads;
- optional WS/RPC use of scoped projection reads when the authenticated session carries `fenixCodeTenantScope`;
- `FenixPairingSessionSnapshot` now carries mandatory `tenantScope`, so the future active bridge can derive local identity from the F1.2b pairing envelope.

Not implemented in this candidate:

- F1.2c active bridge;
- provider execution path;
- production activation;
- DML;
- monorepo changes.

## Identity Contract

Normal T3 local sessions do not carry `fenixCodeTenantScope` and continue using the existing unscoped projection query.

Fenix-scoped reads only activate when the authenticated session has `fenixCodeTenantScope`. That field is reserved for sessions minted from the Code Lab pairing envelope. No WS/RPC request body, query string, thread id, project id, or model setting can choose company/user scope.

The pairing envelope helper rejects malformed scope metadata before any Fenix adapter fetch, using the same active-snapshot validation path as expiry.

## Negative Coverage

`apps/server/src/orchestration/Layers/FenixScopedProjectionSnapshotQuery.test.ts` seeds two tenants with identical projection shapes and verifies:

- unscoped baseline still sees both tenants;
- scoped shell enumeration returns only the scoped project/thread;
- scoped counts are tenant-local;
- scoped snapshot `updatedAt` is recomputed from visible rows only and does not inherit newer foreign-tenant timestamps;
- workspace lookup applies tenant scope before `LIMIT 1`; a duplicate workspace root owned by another user in the same company does not hide the scoped project;
- project read by foreign id returns `None`;
- thread detail read by foreign id returns `None`;
- foreign checkpoint context returns `None`;
- same-company/other-user and other-company/same-user fixtures are both rejected for project, thread, and checkpoint reads;
- in-scope thread detail still includes its own message, checkpoint, and projected session;
- search for a shared phrase returns only the scoped tenant;
- search applies tenant scope before `LIMIT`, including the `limit=1` regression where the foreign tenant is newer;
- malformed and absent scopes return empty/`None` on a populated database rather than falling back to unscoped reads.
- empty scoped snapshots preserve the current `snapshotSequence` instead of resetting to `0`, so snapshot-to-event handoff remains monotonic.

`apps/server/src/server.test.ts` verifies the WS/RPC transport chooses the scoped projection reader when `fenixCodeTenantScope` is present. The test makes the unscoped query throw for shell/search/thread detail and proves `subscribeShell`, `searchThreads`, and `subscribeThread` all pass through the scoped service with `companyId=5,userId=10`.

The same WS/RPC test also covers the non-snapshot escape hatches:

- `subscribeThread` validates scoped thread membership before attaching catch-up replay or live domain-event delivery;
- `subscribeShell` drops live/catch-up events for foreign projects/threads instead of emitting `project-removed`/`thread-removed` with foreign ids;
- `getTurnDiff` and `getFullThreadDiff` validate scoped thread membership before reaching `CheckpointDiffQuery`;
- `dispatchCommand` is denied entirely for Fenix scoped sessions until F1.2c/F1.4 define a reviewed command-field policy;
- a foreign-thread diff and all scoped dispatch attempts fail before the global services are invoked.

`apps/server/src/ws.ts` also has a central Fenix scoped RPC allowlist. When `fenixCodeTenantScope` is present, only the scoped orchestration methods and `serverProbe` can pass the common `observeRpc*` authorization layer. Global server/provider/settings/process, filesystem, source-control, VCS/worktree, review, terminal, preview, and telemetry RPCs fail before their handlers run.

`apps/server/src/server.test.ts` verifies the denylist through real WS/RPC calls for server settings/update, filesystem read/write/search, source-control lookup, VCS worktree creation, terminal open, and terminal attach. It also covers the dangerous dispatch payloads called out during review: `project.meta.update` with `workspaceRoot/scripts`, `thread.create` and `thread.meta.update` with client-controlled `worktreePath`/provider, `thread.turn.start` with `bootstrap.prepareWorktree` plus `runSetupScript`, and `thread.runtime-mode.set` with `full-access`. The same test proves the allowlist remains usable by calling `serverProbe` and scoped `searchThreads`.
